# devBuddy AI — Project Summary

## What It Is

An AI-powered Socratic programming mentor for absolute beginners. The core insight: beginners copy code from AI or Stack Overflow without understanding it. devBuddy meets them there — the user pastes real code they found, and the system builds a personalized learning path from that code, not from a generic curriculum.

The AI never gives direct answers. It guides through Socratic questions and progressive hints.

---

## Core User Flow

1. **Paste code** — user submits code they copied/wrote but don't understand
2. **Analysis** — Code Analyzer Agent extracts concepts, identifies difficulty
3. **Assessment** — 10 questions generated from the user's actual code; user answers them
4. **Gap identification** — score reveals weak areas vs strong areas
5. **Personalized path** — Planner builds 10 lessons covering exactly what they need to understand their code
6. **Learn** — each lesson has animation frames, line-by-line walkthrough, and a practice workshop
7. **Mentor chat** — Socratic AI mentor available throughout; never gives direct answers

## Architecture

### Backend Agents (`backend/app/agents/`)

| Agent | Role |
|---|---|
| `code_analyzer.py` | Parses submitted code, extracts concepts and difficulty level |
| `assessment_generator.py` | Generates 10 questions grounded in the user's actual code |
| `assessment_agent.py` | Evaluates answers, produces score, weak/strong areas |
| `planner.py` | Builds the 10-lesson learning path + generates full lesson content |
| `socratic_mentor.py` | Powers the mentor chat; Socratic mode, 3 hint levels, never gives direct answers |

### Backend Routers (`backend/app/routers/`)

- `auth.py` — register, login, JWT token issue
- `assessment.py` — submit code, generate questions, submit answers, get results
- `learning.py` — get learning path, get lesson, update progress
- `chat.py` — Socratic mentor chat sessions

### Frontend Pages (`frontend/src/pages/`)

| Page | Description |
|---|---|
| `Landing.tsx` | Marketing / entry page |
| `Register.tsx` / `Login.tsx` | Auth |
| `Assessment.tsx` | Code paste → quiz flow |
| `Dashboard.tsx` | Learning path overview, lesson cards |
| `Learn.tsx` | Full lesson view + mentor chat |

### Frontend Lesson Components (`frontend/src/components/lesson/`)

| Component | Description |
|---|---|
| `AnimationPlayer.tsx` | Frame-by-frame cinematic walkthrough with auto-play, dot navigation, slide transitions |
| `CanvasScene.tsx` | HTML Canvas renderer for each animation frame — draws variable boxes, arrows, bezier parent-child connections. Supports tree layout (for recursive/nested concepts) and flat horizontal layout. Dynamic node sizing via text measurement |
| `CodeWalkthrough.tsx` | Split-view line-by-line explainer — code on left (highlighted active row), description + why callout on right, auto-play with 2.8s interval |
| `WorkshopExercise.tsx` | Interactive practice exercise (predict output, fill-in-blank, debug challenge) |

## Lesson Content Format (New Cinematic Format)

Lessons generated by `planner.py` use a structured JSON schema:

```json
{
  "concept_hook": "One-sentence metaphor for the concept",
  "animation_frames": [
    {
      "frame": 1,
      "title": "Cinematic title",
      "code_state": "1-3 relevant lines",
      "canvas_scene": {
        "nodes": [
          { "id": "a", "type": "variable", "label": "energy_budget", "value": "10.0", "color": "sky", "highlight": true }
        ],
        "edges": []
      },
      "narration": "One sentence, present tense."
    }
  ],
  "code_walkthrough": [
    { "code": "line of code", "plain_english": "what it does", "why": "why the programmer wrote it" }
  ],
  "key_concepts": ["concept 1", "concept 2"],
  "workshops": [{ "type": "predict_output", ... }],
  "summary": "One-sentence takeaway"
}
```

Old lessons (with `explanation` + `visualizations`) render in legacy mode automatically — full backward compatibility.

## Canvas Scene Node System

Each animation frame renders a canvas diagram showing variable state:

**Node colors:**
- `sky` — default variable
- `amber` — value changing in this frame (highlight)
- `emerald` — result / output
- `fuchsia` — boolean / condition
- `red` — pruned / failed path
- `slate` — unchanged context

**Layouts:**
- **Horizontal** (default) — nodes left-to-right, arrows show data flow
- **Tree** (auto-detected when any node has `parent`) — recursive subtree allocation, bezier curves connect parent bottom to child top. Used for: recursive calls, nested data structures, branching conditions, call stacks

## Key Design Decisions

1. **Code-first, not curriculum-first** — the user's own code is the anchor for every lesson, question, and example. The AI always asks "have you seen this pattern in your code?"

2. **Socratic only** — the mentor never gives direct answers. Hint levels 0–3 (Socratic questions → concept reminder → point at problem → worked example). This is enforced in the system prompt and is the core pedagogical constraint.

3. **Pre-generate all lesson content** — all 10 lessons are generated at learning path creation time (background tasks), so the user never waits mid-lesson.

4. **Cinematic lesson format** — animation frames with canvas diagrams replace walls of text. Each frame = one atomic code action. The canvas shows variable state visually.

5. **Backward compatibility** — new lesson format (canvas_scene) coexists with old format (explanation + visualizations). Frontend detects format and renders accordingly.

## What's Built vs What's Not

**Built:**
- Full auth flow (register / login / JWT)
- Code submission → assessment → personalized learning path
- Cinematic lesson page (animation player, canvas scene, code walkthrough, workshop)
- Socratic mentor chat with hint levels and code sharing
- Dashboard with lesson progress tracking

**Not yet built:**
- Runtime code execution (run code in browser / sandbox)
- Multi-language support beyond Python (backend is language-agnostic, frontend editor is Python)
- Social / collaborative features
- Spaced repetition / review scheduling
- Mobile-optimized layout
